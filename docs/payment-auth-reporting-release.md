# Выплаты, вход, расчёты и архив — 3 сентября 2026

Область выпуска: пункты 2–5 согласованного аудита. Публичный сценарий присоединения к программе из пункта 1 не изменяется.

## Выплаты

- Перемещение воронки отправляет только новые статусы, не стандартную сумму задания.
- Ноль — явно заданная сумма. Отсутствующее поле сохраняет согласованное значение.
- Существующее начисление сохраняет свою валюту, даже если настройки программы изменились.
- Процент пересчитывается при изменении суммы продажи; изменение заметки не пересчитывает начисление.
- Отмеченный перевод и подтверждённое получение не сбрасываются при редактировании карточки.
- После отметки перевода изменение суммы или этапа блокируется. Возвраты/корректировки подтверждённых выплат не автоматизированы: нельзя имитировать их снятием галочки.
- Отдельная отмена отметки перевода допустима только до подтверждения получения; она сохраняется в истории.
- Отметка перевода и подтверждение получения одноразовы. Повтор не меняет дату события.
- Запись заявки, начисления и события выполняется атомарно с проверкой прочитанного состояния. Конкурирующее изменение возвращает 409 без частичного сохранения.
- Для коммерческой заявки переход в «Оплачено» требует положительную сумму. Задания IMAGE/ENGAGEMENT с фиксированной наградой по-прежнему не требуют продажи клиента.

## Вход

- Миграция 0031 добавляет только уникальный индекс `lower(trim(email))`. Записи не удаляются, не объединяются и не переписываются.
- Перед подготовкой миграции read-only проверка всех 36 пользователей production не выявила нормализованных дублей или пустых email. Если к моменту применения появится коллизия, индекс не создастся; такую коллизию нельзя автоматически «лечить» удалением пользователей.
- Конкурирующая регистрация возвращает ACCOUNT_EXISTS проигравшему запросу.
- Новый код аннулирует старые коды; проверяется последний выданный код, в том числе если он уже использован.
- Условная атомарная запись использует код только один раз. Это действует для активации компании, сброса пароля и входа амбассадора.
- Ошибка отправки письма не восстанавливает предыдущий код.
- Общие D1-счётчики ограничивают вход, регистрацию и коды по доверенному IP и нормализованной почте. Поддельный X-Forwarded-For не создаёт новый лимит.

## Расчёты

- CRM имеет выбор месяца. Часовой пояс расчёта — UTC+5.
- Факт — сумма текущих состоявшихся продаж, чей последний переход в оплаченный этап записан в выбранном месяце. Поздние комментарии и переводы амбассадору не меняют месяц продажи.
- Исторические продажи без события перехода не получают выдуманную дату и не входят в месячный факт. Это не восстановление банковской выписки.
- Потенциал — все открытые сделки в валюте цели, независимо от месяца. Средний чек другой валюты не подставляется в карточки.
- Отчёт считает начисления по approvedAt, переводы по paidAt, подтверждение получения по partnerConfirmedAt. Это разные показатели.
- Суммы выдаются отдельно по каждой валюте. Сохранены старые числовые ключи метрик; при нескольких валютах их общее значение не суммируется. Новые ключи имеют форму `paid:KZT`.
- Показатели в обоих кабинетах рассчитываются одинаково по текущим данным. Исходный metricsJson и ревизии отчёта не переписываются.
- Сводка отчётов считает исходные записи за текущий месяц, а не складывает пересекающиеся отчёты.
- К выплате на конец периода рассчитывается по датам начисления/перевода сохранившихся записей; это не полноценный исторический бухгалтерский регистр возвратов и корректировок.

## Архив

- Завершённые, приостановленные и истёкшие программы остаются в выборе компании для участника.
- Кабинет с одним архивным проектом открывает историю заявок и выплаты, включая подтверждение получения.
- В новых заданиях по-прежнему доступны только активные, неистёкшие программы.
- Блокировка участника, истёкший токен и границы компаний по-прежнему проверяются.

## Проверки и выпуск

Добавлены поведенческие регрессии на SQLite, React/DOM и Cloudflare D1 emulator: параллельные входы/регистрации/коды, конкурентная отметка перевода, валюты, периоды, архив и подтверждение получения.

Перед выпуском: `pnpm lint`, `pnpm test`, `pnpm exec tsc --noEmit`, `pnpm i18n:check`; проверка новой миграции на чистой схеме и на синтетической коллизии. Production формы для тестов не отправляются.

Откат — предыдущая сохранённая версия Sites. Уникальный индекс совместим со старой схемой; удалять его или исторические миграции для отката не требуется. Откат кода не отменяет уже записанные финансовые события.
