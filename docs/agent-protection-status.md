# Кабинет агента: защита и удобство

Ветка `codex/agent-protection`. Изменения подготовлены к проверке в PR, не опубликованы. `main`, production-данные, `.openai/hosting.json`, DNS и переменные окружения не менялись.

## Реализовано

1. Оба обработчика заявок отклоняют собственный email/телефон агента (422, `SELF_REFERRAL`). Телефоны с `+7`, `8`, пробелами и скобками сравниваются после нормализации. Пустые контакты не считаются совпадением. Проверка выполняется до записи заявки и загрузки файлов.
2. Обе публичные формы имеют скрытое антиспам-поле. Заполненное поле отклоняется до обращения к данным. Это дополнительный фильтр, **не замена IP-лимиту или капче**.
3. Все четыре API подтверждения/входа используют общую функцию сравнения хэшей без остановки на первом отличающемся символе. Удалены копии этой функции из авторизации компании и администратора. Формат паролей и токенов сохранён.
4. Неисправные ссылки открывают понятную страницу с входом по email. Добавлены error boundaries с повторной попыткой. Для ошибки в layout агента предусмотрена также родительская граница.
5. Префиксы доменной маршрутизации перечислены явно. Тест обходит страницы `app/` и падает при новом неклассифицированном разделе.
6. [Предложение по единой личности агента](agent-identity-review.md) описывает текущие места группировки и вариант постепенного перехода. Исторические участия не объединялись и не удалялись.
7. Голосовые заявки используют существующее атомарное резервирование кредитов компании. Максимальный резерв — 120 кредитов; после ответа списывается фактический расход, остаток возвращается. Ошибка провайдера возвращает резерв. Результат остаётся черновиком, автоматической отправки заявки нет.
8. В кабинете показан срок **конкретной текущей ссылки**. Детали свёрнуты; рядом есть способ получить новую ссылку. Долгоживущий вход по токену сохранён.
9. Агент получает email при смене проверки/продажи, одобрении вознаграждения и отметке перевода. Массовая отметка выплат собирает одно письмо на email, даже при нескольких программах одной компании. Повторное сохранение без смены статуса не создаёт новое уведомление. Письма не содержат телефонов клиентов или долгоживущих токенов; вход — через email и выбор компании.
10. Страницы/ответы кабинета агента не кешируются. Добавлены `Referrer-Policy: no-referrer` и `X-Robots-Tag: noindex, nofollow` для приватных агентских маршрутов.

## Требует разрешения владельца — пока НЕ реализовано

- IP-лимит двух публичных обработчиков заявок.
- Лимит пяти попыток и временная блокировка `partner/verify`, включая защиту от обхода через повторную отправку кода.

Предложена одна служебная таблица D1 для атомарных счётчиков: хэш ключа, число попыток, конец окна ограничения. Ключи разделяются по назначению: отправка заявки с IP, выдача кода, проверка контакта. Существующие таблицы и записи не изменяются. Нужны согласованные сроки удаления технических счётчиков; хэш IP не следует считать гарантией анонимности.

Запрос согласия отправлен владельцу. Миграций нет, несуществующие колонки/таблицы в коде не используются. **До реализации этих пунктов защиту от перебора в `partner/verify` нельзя считать завершённой.** Тест нового лимита также будет добавлен вместе с ним.

## Проверки и ограничения

- `pnpm lint`: завершён, 0 ошибок; 7 прежних предупреждений об использовании `<img>`.
- `pnpm test`: сборка успешна, 65 тестов прошли, 0 ошибок.
- `tests/mission-workflow.test.mjs` и `tests/agent-account-access.test.mjs` теперь вызывают реальные обработчики и запросы к временной SQLite, а не ищут строки в исходниках.
- Проверены саморефералы, honeypot, дубли, разные компании, сроки ссылок, блокировка доступа, существующий лимит входа агента, отправка файлов и заявок, ошибки и конкуренция голосовых запросов, уведомления.
- Собранный Worker проверяется на HTTP-ответах: недействительные ссылки возвращают 404 с текстом восстановления. UI-компоненты проверены через HTML/DOM без использования реальных персональных данных.
- Внешние отправки писем, Gemini и R2 заменены тестовыми адаптерами. Реальные письма и заявки не отправлялись. Это не проверка доставки в production.
- Email-уведомления используют текущий канал Resend. Отправка ограничена пятью секундами и не отменяет сохранённый статус при сбое. Долговременной очереди/повторной доставки пока нет; гарантированная доставка потребует отдельной работы. WhatsApp не подключался.
- Для новых SQL-тестов требуется Node ≥22.16; это отражено в `package.json`. CI использует актуальную Node 22. Версии зависимостей не менялись.
- Дополнительная проверка `tsc --noEmit` обнаружила существующую в `main` ошибку типа `plannedAt` в `app/dashboard/crm/crm-workspace.tsx:118`. В рамках агентского PR этот посторонний участок не менялся.

Следующий шаг: согласовать служебную таблицу, завершить лимиты и их конкурентные тесты, затем отдельно разрешить публичное обновление. Предложение по единой личности требует отдельного согласования и не входит в миграцию счётчиков.
