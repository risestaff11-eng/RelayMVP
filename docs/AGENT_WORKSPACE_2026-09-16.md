# Упрощение кабинета агента

## Что изменилось

- Главная: реальные начисления по валютам, ближайшие действия и последние клиенты. Нет обещаний заработка на основе максимальной награды.
- Единый раздел «Задания»: мои / все доступные. Старый адрес «Мои задания» перенаправляется сюда.
- Одна точка передачи клиента: сразу форма для единственного принятого задания, выбор задания в остальных случаях.
- Короткие формы: до шести не-файловых полей без обязательного файла. Обязательные поля открыты, дополнительные и голосовой ввод свёрнуты. Сложные формы сохраняют три шага и все проверки компании.
- Черновики: на сервере, отдельно для участия и задания, срок 24 часа; без файлов и аудио. Не записываются в localStorage. Очистка после отправки, выхода из email-сессии и по истечении срока. При недоступной базе выход всё равно выполняется, очистка остаётся по сроку.
- Повторная отправка с одним requestId возвращает уже созданную заявку. Идентификатор привязан к компании, участию и заданию; двойной клик дополнительно блокируется в интерфейсе.
- «Мои клиенты»: поиск имени / телефона / программы, фильтры состояния и программы, требующие внимания выше остальных.
- Проверка, продажа и вознаграждение остаются разными состояниями. Нулевое начисление не заменяется рекламной суммой. Статусы вознаграждения одинаковы в списке, карточке и выплатах.
- Сроки проверки и выплат берутся из существующих правил. По просроченной заявке можно оставить напоминание компании, не чаще раза в 24 часа; это запись в истории, а не отправка в мессенджер.
- Получение денег требует явного второго подтверждения. Платформа не переводит деньги вместо компании. Калькулятор заработка свёрнут.
- В задании можно подготовить клиентскую ссылку и изменить сообщение для отправки. Личная ссылка доступа не передаётся клиенту.
- Компания запрашивает уточнение из истории CRM; агент отвечает текстом и необязательным PDF / изображением до 10 МБ. Исходные данные, авторство и финансовые статусы не перезаписываются.
- Уведомления в кабинете имеют отметку прочтения. Email-изменения сохраняются в очереди: повтор через 5 минут, максимум 6 попыток; обработка при трафике и существующем scheduled handler. Возможна повторная доставка при неоднозначном ответе почтового провайдера; exactly-once для email не обещается.
- На телефоне четыре основных пункта снизу, компактная шапка, крупные поля и кнопки; нижняя навигация скрывается при фокусе ввода. Данные и решение компании предшествуют истории.

## Совместимость

Миграция 0037 добавляет только agent_drafts, agent_email_jobs и partner_profiles.notifications_read_at. Не меняет бизнес-статусы, суммы, атрибуцию и существующие ссылки. Очистка новых зависимостей включена в существующее удаление компании / задания. Агентский вход через email сохранён.

## Проверки

- Изолированная SQLite на настоящей схеме и обработчиках: доступ между компаниями, черновики, TTL, повторные и конкурентные отправки, уточнения, напоминания, email-повторы, курсор уведомлений.
- React + DOM: восстановление черновика, ошибка сети без потери полей, неизменность requestId при повторе, защита двойного клика, двухэтапное подтверждение денег.
- Проверка отображения реальных компонентов с тестовыми данными на 320 / 390 / 1440 px. Это отдельный локальный стенд, а не тестовые записи в рабочей базе.
- Проверка RU/KK словаря, типов, lint и полного набора тестов со сборкой.

Наблюдение за работой живых агентов не проводилось: автоматические проверки не заменяют такое исследование. Следующий продуктовый шаг — проверить, может ли новый агент без подсказки передать первого клиента и найти состояние выплаты.
